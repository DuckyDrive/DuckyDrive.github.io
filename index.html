A gaming and project-discovery platform, specified end to end.

DuckyDrive is one unified application with a catalogue of games, sites, software and repositories; a username-only identity system; and a GitHub-powered publishing pipeline. This blueprint defines the whole of it before a line of product code is written.

Locked decisions

These are confirmed product decisions, not proposals. Every chapter is checked against them.

  • One application. Home, Games, Sites, Repositories, Software, Chat, Library, Settings and Admin are views inside one shell — not separate sites.
  • Games ship separately. Each game is its own repository, deployed to its own path on the same domain and opened full-screen.
  • Username-only accounts. No email required; recovery codes and optional passkeys carry recovery security.
  • No Developer staff role. Game editing requires verified GitHub repository permissions.
  • No chat attachments. Text, emojis and reactions only — no uploads and no external-URL workarounds.
  • Following is quiet. Following a project never produces an update notification.
  • Manual live events. DLES events are started and stopped by staff; no recurring schedules and no seasonal competitions.
  • No developer analytics dashboard. Public statistics only.
  • Three staff tiers only. Owner, Administrator, Moderator — nothing else.
  • Auto-publish after validation. Publishing happens only once the validation gate passes.
  • No seasonal resets. Leaderboards are rolling windows with no reset ceremony and no seasonal badges.
  • Banner announcements. In-game announcements are top-of-screen banners, never centre-screen takeovers.
