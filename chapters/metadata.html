Chapter 09 · Section 23

The duckydrive.json Standard

A small, versioned metadata file at the root of every DuckyDrive game repository. Enough to publish correctly, small enough to fill in for a weekend prototype.

9.1 Persistence rule

Freebuff creates and maintains duckydrive.json whenever a new game is started for DuckyDrive — including in a new chat — using only information that is actually known about the project. The file is validated before deployment or catalogue publication. The user should never have to repeat this instruction.

If a project is clearly unrelated to DuckyDrive, Freebuff does not add the file.

9.2 Minimal valid file

{
  "schema": 1,
  "name": "Neon Drift",
  "description": "A one-button rhythm racer built for keyboard and touch.",
  "type": ["game"],
  "slug": "neon-drift"
}

That is the whole requirement. Everything else is optional.

9.3 Fully populated file

{
  "schema": 1,
  "slug": "neon-drift",
  "name": "Neon Drift",
  "description": "A one-button rhythm racer built for keyboard and touch.",
  "overview": "Longer copy shown on the project page.",
  "type": ["game"],
  "categories": ["rhythm", "casual"],
  "tags": ["one-button", "arcade", "synthwave"],
  "platforms": ["web", "mobile-web"],
  "thumbnail": "./art/thumb.png",
  "screenshots": ["./art/shot-1.png", "./art/shot-2.png"],
  "entry": "./index.html",
  "hosting": {
    "status": "hosted",
    "path": "/neon-drift/",
    "provider": "github-pages"
  },
  "repository": {
    "owner": "DuckyDrive",
    "name": "neon-drift"
  },
  "release": {
    "version": "0.4.1",
    "date": "2026-11-20",
    "notes": "Added two tracks and fixed touch input on iOS."
  },
  "featured": false,
  "capabilities": {
    "sdk": "1.0",
    "playSessions": true,
    "liveEvents": ["announcement", "visual-weather"]
  }
}

9.4 Field reference

Field Type Required Rules
schema integer Yes Currently 1. Unknown major versions are rejected; unknown minor additions are ignored.
name string Yes 1–60 characters, plain text.
description string Yes 10–200 characters, plain text, no HTML.
type string[] Yes From game, site, software, experiment, repository. At least one.
slug string Required when hosting.status is hosted Lowercase a-z0-9-, 2–40 chars, unique across the platform.
overview string No Up to 4,000 characters, Markdown subset (paragraphs, lists, links, bold).
categories string[] No From the controlled game category list. Max 6.
tags string[] No Max 12, lowercase-hyphenated, max 24 chars each.
platforms string[] No web, mobile-web, desktop, controller.
thumbnail string No Relative path under the repository, or https URL on an allowed host. PNG/JPEG/WebP, ≤ 2 MB, 16:9 recommended.
screenshots string[] No Max 8, same rules as thumbnail.
entry string No Relative path to the HTML entry document; defaults to ./index.html.
hosting object No status ∈ hosted, not_hosted, unknown; path must match /^\/[a-z0-9-]+\/$/; provider ∈ github-pages, external.
repository object No owner and name; must match the repository being scanned or be explicitly declared on a fork.
release object No version (semver-ish string), date (ISO 8601), notes (plain text). Releases in GitHub override these values.
featured boolean No A preference; staff still decide actual featuring.
capabilities object No sdk version, boolean feature flags and a liveEvents array of supported DLES capabilities.

Unknown fields are preserved and ignored, never rejected, so a newer game can publish metadata before the platform understands it. A warning is logged so the platform can grow into the field.

9.5 Validation errors and warnings

Code Level Meaning
E_SCHEMA_VERSION Error Missing or unsupported schema.
E_REQUIRED Error name, description or type missing/invalid.
E_SLUG_FORMAT Error Slug fails the pattern.
E_SLUG_TAKEN Error Slug already reserved by another project.
E_URL_UNSAFE Error A URL uses a disallowed scheme or escapes the repository root.
E_CATEGORY_UNKNOWN Error Category not in the controlled list.
E_ASSET_MISSING Warning Declared thumbnail/screenshot does not exist. Field dropped.
W_TOO_LONG Warning Description or overview exceeds the recommended length and is truncated in listings.
W_UNKNOWN_FIELD Warning Field not understood by this schema version; preserved.
W_NO_ENTRY Warning Hosted project without a resolvable entry document.

Warnings never block publication. Errors do, and are shown to the contributor with the exact path (hosting.path) that failed.

9.6 Safety rules

  • Paths are resolved relative to the repository root and must stay inside it — ../ escapes are rejected.
  • URLs must be https: or repository-relative; javascript:, data: and file: are rejected.
  • Displayed strings are escaped as text; the Markdown subset in overview allows no raw HTML, no scripts, no event attributes.
  • The metadata file can never declare permissions, roles, staff status or capability overrides that grant privileges. capabilities describes what a game supports, not what it may do without authorisation.

9.7 Versioning and migration

  • schema is an integer. Adding an optional field does not bump it; changing meaning or type does.
  • A new schema version ships with a migration that maps old fields forward; both versions are accepted for at least one release cycle with a warning on the older one.
  • The platform stores the raw file plus a parsed snapshot, so re-validation after a schema change is a re-parse rather than a re-scan.
  • If a required field is removed in a future version, the migration supplies a default from the repository where possible, and otherwise marks the project for contributor review rather than hiding it silently.
