Chapter 06 · Sections 12-14

Friends, Chat, Messaging & Notifications

Text, emojis and reactions only. No attachments in public chat or private messages, and no embedding workaround.

6.1 Social graph

Action Rules
Send friend request Requires a public profile or a shared room; blocked users cannot request. Max 20 pending outgoing requests. Duplicate requests collapse into one.
Accept / reject Recipient only. Accepting creates a symmetric friendship; rejecting deletes the request without notifying the sender that they were "rejected" beyond the request disappearing.
Remove friend Either side, immediate, no notification with a reason.
Block Immediate, one-sided from the blocker's perspective, symmetric in effect. Ends friendship, cancels pending requests, prevents messages and requests.

Friendship state is stored as a pair-normalised row so a single row represents both directions.

6.2 Presence and activity

Online status is opt-in and off by default. It is derived from recent authenticated activity (last 5 minutes) with a coarse label ("Online" / "Active recently" / nothing). "Now playing" appears only when the game integration reports it and the user has enabled sharing it. Presence is never inferred from IP geolocation.

6.3 Public chat

Initial rooms: General, Gaming, Development, Announcements.

  • Guests can read public rooms; posting requires an account.
  • Rooms are created and archived under a staff permission. Archived rooms become read-only and stay visible.
  • Messages support plain text (max 1,000 characters), emojis and reactions (one per user per message, multiple emoji types).
  • No attachments, no images, no files, no link previews generated from uploaded media. URLs are rendered as plain links subject to a safe-scheme check.
  • Rate limits: 5 messages per 10 seconds per account, with a soft warning at 3 and a temporary mute on repeated bursts.
  • Duplicate-message detection collapses accidental double sends.
  • Slow mode can be enabled per room by staff (minimum interval between messages).

Moderation: staff can remove a message (visible tombstone "Message removed by moderator" with reason category), pin up to 10 messages per room, mute a user for a room, and review reports. Announcements room is staff-post-only; admin announcements also appear in the notification inbox for users who subscribe to announcements.

6.4 Private messaging

  • Friend-only by default. A setting allows messages from "friends only" or "nobody"; there is no open inbox.
  • One-to-one conversations only. No group DMs in v1.
  • Text, emojis and reactions. No image, video or file attachments, and no workaround via external URLs or embeds.
  • Deletion: "Delete for me" removes it from the requester's view only. "Unsend" is available for 10 minutes, replaces the message with a tombstone for both participants, and retains a moderation audit record (author, timestamp, room/conversation id, reason) without the body after 30 days.
  • Read receipts are optional and off by default; when off, the sender sees only "delivered".
  • Blocking ends the conversation's ability to send, and existing messages remain visible to the blocker.
  • Reporting a message includes surrounding context for moderators only.
  • Rate limits and spam detection apply; first messages from a new friend are limited to 10 per minute.

6.5 Notifications

A single inbox with categories the user controls:

Category Triggers Default
Comment replies Someone replies to your comment or reviews a project you own On
Comment likes Someone likes your comment On, digestible
Achievements You unlock an achievement or tier On
Friend requests New request, accepted request On
Friend activity Friend comes online or starts playing, when both opt in Off
Live events DLES event announcements On
Admin announcements Platform announcements On
Account security New login, password change, recovery use, factor change Always on, non-disableable
Game updates Only when a user explicitly subscribes to a supported notification type for that project Off

Following a project never generates a notification when it updates. There is no code path that converts a follow into an update notification; the subscription for game updates is a separate, explicit, per-project action.

Behaviour: unread badge on the inbox, mark one/mark all read, history retained 90 days, duplicates de-duplicated by a deterministic event key (so a retried job cannot double-notify), and per-category quiet hours.

6.6 Data and safety

  • Messages are stored with author id, room or conversation id, body, timestamp, edit state and moderation state.
  • Reports keep a snapshot of the reported content so later edits or deletions cannot erase evidence.
  • Retention: public chat 24 months, DMs 12 months after last activity, reports and moderation records per Chapter 13.
  • Access control is enforced with Row Level Security: a participant can read their conversation; a moderator can read reported content only in the context of an assigned report, and every such read is audited.
  • No end-to-end encryption is claimed. Privacy statements describe server-side storage, retention and staff access honestly.

6.7 Realtime transport

Chat and presence use the realtime channel per room with:

  • one subscription per open room, closed on route change,
  • server-generated sequence numbers for ordering, with client reconciliation on reconnect,
  • resume-from-sequence on reconnect, backfill up to 50 messages,
  • initial connection authorisation via a short-lived token issued by the server that encodes room membership — the client never chooses its own identity,
  • degraded mode: if realtime is unavailable, the room falls back to polling every 10 seconds and shows a banner.
