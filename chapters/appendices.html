17.1 Validation register

Item Type Status Decision needed
Username-only auth on the provider Technical assumption Unvalidated Ship adapter, or move identity to a session service.
Free-tier database/storage/realtime limits External constraint Unvalidated Measure in Phase 0; define upgrade trigger.
GitHub Pages for main app + N game paths Technical assumption Unvalidated Prove two concurrent game deploys in Phase 1.
GitHub App least-privilege scopes Technical assumption Unvalidated Confirm read-only discovery plus per-action permission checks.
Webhook reliability without duplicates Technical assumption Unvalidated Idempotency already designed; verify delivery behaviour.
Realtime concurrency at launch External constraint Unvalidated Load test in Phase 10.
Trending window of 14 days Recommended default Provisional Review after 30 days of real data.
Daily XP caps Recommended default Provisional Tune from ledger data.
Avatar/banner size limit of 2 MB Recommended default Provisional Review against storage budget.
Whether an optional email may ever be added Owner decision Not approved Not implemented; no hidden path exists.

Decisions deliberately not defaulted (Owner input required): whether to add optional email in future, whether group DMs are ever in scope, and the final choice of paid tier when free limits are reached. Everything else in this document is defaulted so delivery is not blocked.

17.2 Glossary

Term Meaning
DuckyDrive ID The central username-only identity used across the ecosystem.
Project Any catalogue entry: game, site, software, experiment or repository.
Type What a project is (independent of hosting).
Hosting status Whether a project is currently deployed (hosted, not_hosted, deployment_failed, unknown).
Discovered at When DuckyDrive first validated the project.
Release date When the project was first released, per GitHub or metadata.
Latest release at Timestamp of the newest public release; drives "Recently updated".
Validated Passed every check in the publishing gate.
Withheld Keeper record that is not public because validation or visibility failed.
Favourite A bookmark, counted publicly.
Follow Interest in a project's future; never produces notifications.
Saved Private bookmark, not counted publicly.
Collection User-curated list, optionally public.
Slug Lowercase path-safe identifier, reserved platform-wide.
DLES DuckyDrive Live Events System.
Capability manifest The list of event features a game declares it supports.
SSO Single sign-on across DuckyDrive ecosystem sites using DuckyDrive ID.
RLS Row Level Security in Postgres.
Owner The single protected account with ultimate authority.

17.3 Appendix A — Example metadata files

Minimal:

{ "schema": 1, "name": "Neon Drift", "description": "A one-button rhythm racer.", "type": ["game"], "slug": "neon-drift" }

Invalid (blocked) — absolute asset path and category outside the vocabulary:

{
  "schema": 1,
  "name": "Broken",
  "description": "Demonstrates validation failures.",
  "type": ["game"],
  "slug": "Broken Game",
  "categories": ["shooter"],
  "thumbnail": "/assets/thumb.png"
}

Expected: E_SLUG_FORMAT, E_CATEGORY_UNKNOWN, E_URL_UNSAFE — project withheld, errors shown to the contributor with exact field paths.

17.5 Appendix C — Diagrams

Publishing pipeline:

flowchart LR
  A[GitHub repo] -->|webhook or daily scan| B[Webhook receiver / scanner]
  B --> C{Signature + idempotency}
  C -->|fail| X[Log and drop]
  C -->|pass| D[Parse duckydrive.json + metadata]
  D --> E{Validation gate}
  E -->|error| F[Withheld, reason recorded]
  E -->|pass| G[Project upsert]
  G --> H[Catalogue + search index]
  G --> I[Release history]
  G --> J[Deployment status check]

Permission check for a game edit:

sequenceDiagram
  participant U as Contributor
  participant API as Edge Function
  participant GH as GitHub API
  participant DB as Postgres
  U->>API: PATCH /projects/{id} (session cookie)
  API->>DB: load session → user_id
  API->>DB: load project → repository
  API->>GH: check repo permission for user's GitHub identity
  GH-->>API: admin / push / read / none
  alt permission sufficient
    API->>DB: update project + audit row
    API-->>U: 200
  else insufficient
    API-->>U: 403 permission_denied
  end

DLES lifecycle:

stateDiagram-v2
  [*] --> Draft
  Draft --> Active: staff start (manual)
  Active --> PartiallyActive: some servers unreachable
  PartiallyActive --> Active: servers reconnect
  Active --> Stopping: stop or emergency stop
  PartiallyActive --> Stopping: emergency stop
  Stopping --> Ended: all restores acknowledged
  Stopping --> Ended: timeout, unreachable servers flagged
  Ended --> [*]

17.6 Appendix D — Proposed tables at a glance

-- Illustrative shape only; real migrations are versioned SQL.
create table projects (
  id uuid primary key default gen_random_uuid(),
  slug text not null unique,
  name text not null,
  description text not null,
  overview text,
  visibility text not null default 'withheld'
    check (visibility in ('public','withheld','hidden')),
  hosting_status text not null default 'unknown'
    check (hosting_status in ('hosted','not_hosted','deployment_failed','unknown')),
  discovered_at timestamptz not null default now(),
  latest_release_at timestamptz,
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now()
);
create index projects_visible_new on projects (visibility, discovered_at desc);
create index projects_visible_updated on projects (visibility, latest_release_at desc);

create table ratings (
  user_id uuid references users(id) on delete cascade,
  project_id uuid references projects(id) on delete cascade,
  score smallint not null check (score between 1 and 5),
  updated_at timestamptz not null default now(),
  primary key (user_id, project_id)
);

create table xp_ledger (
  id uuid primary key default gen_random_uuid(),
  user_id uuid not null references users(id) on delete cascade,
  amount integer not null,
  reason text not null,
  ref text not null,
  created_at timestamptz not null default now(),
  unique (user_id, reason, ref)
);

17.8 Final statement

This document specifies DuckyDrive. It contains no application code, creates no repositories for the platform, deploys nothing and configures no provider. The site it is published on is documentation. Implementation begins with Phase 0, and every phase begins only when its prerequisites have exited successfully.
